# Milvayo

<!-- impeccable:product-schema 1 -->

## Platform

adaptive

## Users

People managing independent projects, tasks, delivery evidence and related governance. The product owner develops and tests on an Android phone using Termux/Debian. Android portrait is the primary design scene; web remains a supported working surface.

## Product Purpose

A local-first work-management studio connecting tasks, schedules, boards, sprints, releases and project governance, with explicit evidence and verification rather than inferred remote outcomes.

## Operating Context

Existing React Native / Expo SDK 58 app with React Native Web, AsyncStorage and the installed RNGH 3 / Reanimated 4 stack. The owner approved promotion of the existing `redesign/` copy into the main application for 0.7.0 on 2026-11-06. The main folder is now the working application; the superseded source checkout and temporary promotion copies were removed after owner build confirmation. The owner manually tests Android Expo Go and APKs.

## Capabilities and Constraints

Preserve tasks/details, scheduling/dependencies, Kanban, sprint history, projects/programs/portfolios, releases, tests, contributors/time/costs, automations, reports/activity, specifications, backup/import/export, themes and workspace controls. Retain schema compatibility, normalization/recovery, cycle checks, release evidence and frozen sprint history. No backend invention, copied reference assets, dependencies without need, builds, Playwright, emulators, heavy profiling, automatic commits, Git branch merges or pushes. Source promotion was explicitly approved; it preserves main Git history and private signing files.

## Brand Commitments

Milvayo name and original Board mark remain. The user explicitly replaces the previous visual compositions and interaction conventions, with premium mobile task-product craft informed by the actual `designexamples/` images. All ten accent preferences and System/Daylight/Dark/AMOLED remain supported. References are design inputs, not licensed shipping artwork.

## Evidence on Hand

`report.md` (read in full, 544 lines), `AGENTS.md`, existing source/tests, user-supplied Android and web diagnostic observations, and 131 visual reference files in `designexamples/`. The user confirmed this folder supersedes the earlier paths in the report. Native cause/acceptance require device evidence; no native runtime success is implied by browser tests.

## Product Principles

- Make current work and its next action clear before advanced controls.
- Preserve capability while revealing uncommon operations contextually.
- Make portrait navigation, sheets, forms and feedback intentional.
- Treat speed, accessible contrast and reliable persistence as design requirements.
- Keep changes reviewable on `work`; the owner subsequently reported a successful Expo build and explicitly authorized the 0.7.0 commit and push to `work`. Future commits, pushes, merges, deployments and builds still require appropriate authorization.

## Accessibility & Inclusion

Named controls, sensible Android touch areas, readable type and contrast, screen-reader semantics, keyboard behavior on web, reduced-motion support, and no animation that blocks work.

Latest explicit direction: premium neutral dark and AMOLED, with complete structural redesign and new real-data charts. Personal accents must not tint page backgrounds. The owner rejected the first visual pass as insufficient. Pinch-to-zoom is reported fixed in their own test; retain that implementation.
