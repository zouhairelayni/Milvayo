# Security verification

The emulator suite tests real HTTP token verification/authorization plus Firestore, Storage and RTDB rules. Default npm test intentionally marks emulator integration Not run; run npm run test:cloud:running with the local suite, or npm run test:cloud to start/stop it reproducibly. Never replace a skipped emulator test with a source-only pass.

Tested attack classes include signed-out and unrelated-tenant reads/queries; direct nested writes; role/entitlement self-promotion; platform-versus-org separation; project overrides; viewer writes; attachment confidentiality and MIME restrictions; duplicate mutations; forged bases; invalid/oversized fields; dependency cycles; atomic failure; revision recovery; invitation theft/replay; seat races; RTDB ACL forgery/room access; multiple sessions; grant/member revocation; simulated webhook forgery/replay; concurrent grant ordering; unlicensed guests/editing; resource-cap races; last-owner protection; group membership validation; platform role/configuration separation; authorized watcher/mention targeting; immutable messages and history pages; private notifications; and interrupted staged recovery with tombstones and conversation history. Unit tests cover journal corruption/interruption, account/workspace boundaries, frozen sprint history and backup checksums. Final counts/evidence live in docs/qa/cloud-084/REPORT.md.

Observed/fixed during development: RTDB test namespace mismatch; ACL grant ordering; stale cached project access; unbounded journal rows; coalesced logical edit capture; incompatible Admin credential initialization found by live Web sign-in; fixture mocks for the new optional presence hook. A final direct-SDK review also removed receipt reads that could bypass later project revocation and blocked shared hierarchy records under explicit project denials. Rules were kept restrictive while fixing the affected code/tests.

Prototype Security Rules enforce active membership, explicit scoped grants, default deny and server-only durable writes. They require review before broad sharing. Emulator success is not a production security certification. Outstanding risks: physical cached-data threat model, same-origin multi-tab local writers, index/deployment packaging, rate limiting/App Check, real auth providers, storage download-token handling and support-access policy. No production resources were modified.

## v0.8.5 changes

The independent-task path validates exact normalized task shape, identical record envelope/order, known immutable stale bases and current custom-field configuration. Unsupported structural patches fail closed or use full canonical validation. Fresh membership/grant/seat checks precede receipt replay. New differential, scaling, malformed-patch, no-op, legacy replay, frozen wire, journal crash and single-writer tests extend the original adversarial suite; assertions were not weakened. Final run results and any infrastructure blockers are in [cloud-085](../qa/cloud-085/REPORT.md). Physical shared-device confidentiality, production App Check/rate limiting and real multi-device soak remain gates.
