# Backup and disaster recovery

Existing JSON/niyav project/workspace exports and local snapshots are unchanged. New cloud exports use milvayo.cloud.backup.v2 with cloud schema 1, organization/workspace scope, sequence, granular records, collaboration families and two SHA-256 checksums. The v1 record-only reader remains compatible. Export requires explicit export permission for every included project. Record versions, soft-deletion tombstones and append-only audit remain available after mutations. No permanent purge command is added.

Settings → Cloud recovery verifies checksum/scope/duplicate keys and previews affected records before an explicit confirmed restore. Optional project/task filters narrow an in-place restore; task recovery includes canonical comments/time/reminders. Canonical validation rejects missing dependencies or invalid Canvas references before mutation. In-place recovery preserves unrelated current records and revision-checks competing edits. Failure commits nothing; restored changes create versions and audit metadata. A single transaction accepts at most 100 changes.

For a complete backup exceeding that limit, choose a fresh workspace ID and confirm Restore into new workspace. Canonical records and collaboration messages/conversations/watchers/notifications upload in resumable bounded batches. Finalization verifies both manifests, references, sequence uniqueness and checksums before atomic activation. Importing workspaces cannot be read through the API. Failed or incomplete staging remains hidden and resumable. Soft-deletion tombstones are staged too, so archived conversations retain their task/project references without making deleted work active again. Explicit authorized task restoration makes its retained conversation available. The original workspace remains untouched. Only the restoring administrator receives an initial grant; copied watcher relationships never grant membership or access. Restored messages retain their historical actor but are marked restored with the current restoring actor; copied notifications are marked read to prevent redelivery. A fresh recovery audit records provenance. Prior source revision/audit history is retained in the source workspace and emulator export rather than rewritten as new history.

npm run cloud:export writes a new timestamped Local Emulator Suite export under ignored .emulator-data. Restart with npm run emulators -- --import <directory>. Export/import was executed with synthetic data. Managed Firestore backups, retention enforcement, PITR, cloning and protected off-device recovery are not emulator-verified; no production backup or PITR success is claimed.
