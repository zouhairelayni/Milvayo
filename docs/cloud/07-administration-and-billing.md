# Administration and simulated licensing

Settings → Firebase emulator contains explicit sign-in/publish/open controls, organization administration, scoped workspace/project roles, UID-targeted invitations, member revocation, seat capacity, audit metadata, authorized project summaries, separate platform controls, cloud export and previewed recovery. Controls use existing themed primitives and responsive folds. Backend checks apply independently of control visibility. An ordinary organization owner receives no platform role. The explicit synthetic seed command bootstraps one local platform owner.

Organization tools manage shared display names, teams/departments, member roles, per-resource seat caps and allocations, license release, simulated billing history, configured retention and independent organization creation. Groups validate active same-organization membership and department references; they do not inherit confidential project access. Only an organization owner may change administrative roles, and the last active owner cannot be demoted. Guest invitations permit viewing/commenting without consuming a paid seat. Editing grants and commits require a licensed seat. Resource allocations count the same person once in the organization pool, with transactionally enforced resource caps. Releasing a license removes resource allocations and reduces editing grants to commenter; revocation denies access altogether.

Payment state, grace-period hooks, capacity changes and refunds use local provider-neutral events, HMAC verification, bounded event age and actor-authorized duplicate-ID/hash suppression. The public fixture signing key is not a production secret or permission. Billing managers may change capacity and allocations; they receive no project-content access. No real payment API is called and no final subscription pricing is hardcoded.

Platform administration exposes organization metadata, actual current-worker requests/failures, sampled handler latency/heap, instrumented document-operation lower bounds, local feature flags/release settings and audit history. Owner/security roles manage application platform roles; owner/security/release manage configuration. Platform roles never imply private content access or Google Cloud infrastructure IAM. Telemetry covers this worker only, resets with its process, and labels uninstrumented Storage traffic and production costs explicitly. Client RTDB counters report payload bytes and connection events, excluding protocol overhead.

Commercial plans, provider/store billing, live refunds, infrastructure IAM, time-limited support access and complete service-wide billing/security monitoring remain future integration work. Retention settings are configured-only: saving a policy does not purge data. Portfolio/program titles use explicit project grants and allocation scopes; there is no implicit hierarchy escalation or separate PMO permission engine.
