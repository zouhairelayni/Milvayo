# Incremental sync and conflicts

Store put validates first and captures every accepted domain transaction. A separate scoped journal contains canonical confirmed records, optimistic local records, ordered operations, actor/scope, IDs, base data/revision, timestamp, retry state, exact sent payload and status. Journal data is sharded into 100,000-character chunks; a checksum-protected manifest pointer publishes a complete generation only after all chunks succeed. The previous generation is retained; corruption fails closed. Large strings do not become oversized Android rows.

A mutation uses a UUID idempotency key. The first sent payload is durably fixed before network delivery. Lost acknowledgements resend that exact payload. Server receipts bind mutation ID, actor and content hash; replay rechecks current permission. Concurrent independent top-level fields merge only against a known immutable server version. Same-field text, array/order, deletion-versus-edit and unknown-base conflicts stop the ordered queue, retaining payloads for export. Task status, parent moves, dependencies and Canvas/group changes still pass canonical validation. Server sequence numbers determine incremental ordering, not client clocks.

Network errors use exponential retry with jitter, capped around one minute. Authentication/permission/validation/conflict failures stop the operation for recovery. The client polls incremental changes while explicitly connected. Record cache hits avoid rereading unchanged content, but membership/grants are rechecked. Atomic mutations acknowledge related changes together; partial server validation failure commits nothing. Structural imports use staged checksum-verified activation, not an oversized transaction. One in-place restored mutation is bounded to 100 changes. Larger complete recovery uses checksum-verified staged activation of a fresh workspace. Conversation requests are durably queued with fixed mutation IDs; lost acknowledgements and process restarts preserve their identity.

An opened remote workspace is borrowed: an untouched local source is saved in a lease. Disconnect, revocation, workspace switch and cold-start recovery restore that source. Pending cloud edits remain in their scoped journal; reconnect hydrates those edits before reconciliation. Explicitly published local work remains local on disconnect. User-created exports cannot be remotely recalled. The current same-origin, multi-tab local-store writer limitation is not claimed solved.

Conflicts: export sync recovery and a local backup before changing anything. Reconnect to the same scope to retry transient errors. For competing text, retain both versions, reconcile the intended value, and publish a new explicitly chosen cloud workspace if the blocked queue cannot be safely replayed. No silent last-writer-wins or automatic text CRDT. A dedicated conflict-resolution editor remains a production readiness item.

## v0.8.5 saving and conflicts

Task text drafts persist independently of explicit Save. Blur commits the completed field locally; Save/Done commits the combined validated draft, flushes local persistence, consolidates compatible unsent task changes and awaits the existing backend acknowledgment. Status/assignment actions synchronize promptly; editing checkpoints default to 45 seconds and are configurable from 30–600 seconds. Ten minutes is experimental, not the default. Cloud acknowledgment is reported only after the queue receives its server receipt. Offline work stays queued.

Only newly prepared mutations are compacted and frozen durably before first delivery. Previously sent v0.8.4 payloads replay verbatim. Settings exposes retained local/remote field comparisons and explicit revision-checked resolution; original conflicted mutations remain archived. Deleted-record conflicts retain intent and use the existing authorized recovery workflow. No silent overwrite/CRDT is added.

Foreground incremental polling backs off from 5 to 60 seconds on unchanged work; background uses 120 seconds, focus resets and explicit Save refreshes immediately. Conversation polling backs off from 3 to 30 seconds and 120 seconds hidden. Global same-origin Web Locks now prevent competing local writers before workspace/index/recovery access; unsupported browsers fail closed. This replaces the prior single-tab limitation with explicit single-writer exclusion and takeover, not simultaneous writers. See [QA](../qa/cloud-085/REPORT.md).
