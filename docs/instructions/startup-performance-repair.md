# Checking the startup and responsiveness repair

This repair is designated 0.7.10 / Android 80 / iOS 80. Historical evidence was collected with the 0.7.9 label; current 0.7.11 includes this repair plus the controls update in `release-0711.md`. The main source is the working candidate, per the owner’s corrected instruction. No packages need installing. Use the existing Termux/Metro session; the agent did not restart a development server or run a build. Keep app data and signing files.

1. Fully close and relaunch Milvayo; confirm a new diagnostic run ID. Check Dark, Daylight, AMOLED and a different accent. The original N should morph continuously into the selected-color Board, without replay after tab changes or warm background/resume. Cold playback is 1.1 seconds, followed by a final frame rather than a one-second timer. With reduced motion enabled, the final Board appears directly. Slow or failed-safe storage must retain the opening layer until readiness, then reveal the workspace or existing safe error.
2. In Settings → Diagnostics → Performance monitor, copy the report after five comparable cold launches. Keep the same installed runtime, appearance and workspace. Compare normalization complete, theme ready, shell first render/commit, native layout callbacks, logo first UI frame callback/completion, workspace revealed and the first-interactive-frame JS estimate. Logo frames/max-gap/playback reflect the UI clock; milestone receipt can still lag a busy JS thread. These are not OS launch/FPS measurements.
3. Open Projects with a realistic large workspace. Scroll, search, open a project, enter details, go back, and rotate the phone. Edit a project name, scroll well away and back, and confirm the unsaved draft remains. Rejected saves retain it; Cancel discards it. Check long names/large budgets at narrow widths and enlarged system text. Read `projects`, `projects/card`, `projects/detail`, mutation, projection, normalization, recovery-budget and serialization samples to identify the source of any remaining one-second stall.
4. Put at least 12 cards in a Board list. First five mount; scroll within that list to load the next five near its end. Other lists and hidden tabs must not load more by timer. Wheel, keyboard and accessibility scroll actions work too. A filter change resets the window to five. Loaded cards are retained for the current board view so title drafts and active responders are not recycled away.
5. Check quick vertical scrolling cancels pending long presses, then hold a card and drag within/across scrolled lists. Drag near the target’s top/bottom to auto-scroll. Drop after the last mounted card and confirm it lands before the next unseen task, including with filters active. Check that held cards are not clipped and list levitation still appears above the board ribbon. Edit a title, scroll away/back, and verify the draft. Add/copy/archive/delete and empty lists remain usable.
6. Repeat Android Timeline pinch and Days/Weeks/Months → Days, plus web Timeline zoom/scroll. Check all tasks/dates/dependencies remain intact, no Reanimated warnings, no JS exceptions, and no startup replay after backgrounding.

Standard production React omits its normal Profiler callbacks. Development/profiling-capable runtimes still report their actual React durations; production now has a separately labelled screen render-to-commit section. Those estimates include scheduling and child work, exclude child-only commits unless separately instrumented, and do not equal the earlier development React CPU measurements. Do not compare unlike columns as controlled benchmarks.

Real Android startup, native frame pacing, TalkBack/large-font behavior, nested scrolling/clipping and Projects timer-delay improvement remain owner acceptance gates. Local JSX/CPU/source-render tests cannot certify them. Do not uninstall or clear storage. Reversal is a reviewed restoration of this repair’s changed files against checkpoint d786468 with its matching lockfile, preserving unrelated ZIP changes and all private signing material.
