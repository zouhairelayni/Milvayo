# Smart Save and local synchronization

Update in place on `work`. Keep a local JSON/niyav backup and any pending cloud recovery export before Termux acceptance. Package/lock/Expo version is 0.8.5/build95. Existing workspaces and import formats do not change. Do not clear app storage.

Open an existing task and type in its title, description or Planning & delivery fields. A scoped draft is written to this device without waiting for Save. Leaving a field commits it locally through existing model validation. Save commits the combined draft, flushes local persistence and synchronizes queued edits if connected. Done and closing the sheet use the same save path. Status and assignment changes synchronize promptly. An unchanged Save sends no cloud mutation. New-task creation keeps its explicit Save task action.

“Draft saved on this device” and “Saved on this device · cloud synchronization pending” do not mean the server accepted the change. “Cloud acknowledged all queued changes” requires an actual server acknowledgment. Network failure leaves queued work local. Reconnect to the same host/account/organization/cloud/local-workspace scope to replay. Auth is memory-only: sign in again after restart before reopening borrowed cloud work.

The periodic checkpoint defaults to 45 seconds; Settings → Firebase emulator exposes the interval policy. The UI offers 30, 45 or 60 seconds; the session experiment API also accepts up to 600 seconds, with a correspondingly long collaboration delay. Explicit Save/Done/status/assignment bypasses that wait. Idle reads back off to reduce traffic; focus or an explicit sync refreshes sooner.

If fields conflict while editing, compare the retained draft and current task before choosing. Cloud conflicts appear in the Firebase emulator panel: load the comparison, inspect your proposed data against the current cloud version, then deliberately choose the intended version. A remote change after comparison requires another comparison. The original mutation remains in the recovery journal. Deletion conflicts require the existing authorized cloud recovery flow; export pending intent first. No local edit is silently discarded to make the queue green.

On Web, keep one writing tab per origin. A second tab shows an explanation and does not touch shared workspace data. Close the first tab and reload the second to take over safely. Web Locks support is required; unsupported/insecure browser contexts fail closed. This protects the shared workspace index as well as journals. Independent collaborators should use separate authorized clients/devices, not simultaneous writers in one browser origin.

Local drafts and journals contain private data. Scoped keys are not device encryption. Keep the device locked; never delete pending recovery data merely to clear an error. Journal storage migrates to v2 chunks while preserving legacy reads and a prior valid generation. Before reverting to v0.8.4, recover/export all v2 pending work or retain the new reader. Detailed update/rollback and remaining gates: [QA policy](../qa/cloud-085/privacy-and-readiness.md).

Run `npm test` for local regressions. When coordinated emulators are available, `npm run test:cloud:running` runs actual security tests; `node src/cloud/tools/benchmark085.cjs` is a bounded but potentially expensive experiment and is not needed for daily phone development. Avoid concurrent stress on the phone. For Web development use `EXPO_OFFLINE=1 npx expo start --web`; retain normal Termux Fast Refresh. No production build, commit or deploy is required to use these changes locally.
