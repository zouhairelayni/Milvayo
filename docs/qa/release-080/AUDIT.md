# 0.8.0 global audit and fixes

Reviewed the local-first Expo/Web app and its new Canvas for a single-device owner, with typical 40-object and stress 200-object boards. Static binding/import and worklet-order checks cover all 250 source modules. Existing tests cover the wider application. This is an engineering audit, not a claim that every device/runtime defect has been eliminated.

The read-only audit followed Ponytail Audit, then the owner's explicit instruction to fix confirmed findings authorized the patches. RN performance/gesture/SVG guidance informed the native paths; UI/UX Pro Max, frontend-design, Impeccable and bundled Unslop guided the restrained menu/layout review. Unslop is by Damir Sokolovsky, CC BY 4.0; see PLAN.md. No external branded source or assets were transplanted.

Routing uses four midpoint ports, outward stubs, clearance and a bend cost, following the Timeline's principles without changing its fixed-row router. Opaque elements are obstacles; transparent group frames and freehand bounding boxes are not. S-curves and direct lines are accepted only when clear; otherwise routed segments avoid the boxes. The search is bounded. Physically contained endpoints or exhausted searches retain their connection records without drawing through content; moving the objects permits a new route. Labels and double-edit picking follow rendered paths.

Map checked: App.js → src/app/ModernApp.js → screen registration/retention/header actions; model/import/recovery/store mutation and durability queue; Canvas library/editor/gesture lifecycle; source adapters and canonical navigation; SVG/PNG/CSV/board backups; WBS cache and initial camera. Timeline duration/dependency logic and sprint lifecycle/history were not rewritten. No conflict markers, unresolved bindings or eager forward worklet captures remain in the scanned source. Import/path/JSX tests remain the separate executable checks.

Remaining acceptance gates are recorded in REPORT.md. Secure remote sharing is unavailable in this local source and remains disabled; no client-only role is presented as authorization. Native mount/frame, physical keyboard/screen-reader behavior and live Web responsiveness require device/runtime acceptance. Static Chromium fixtures and Node timings do not establish those results.
