# Privacy, migration, readiness and reversible update

Auth remains memory-only. Host/actor/org/cloud workspace/local workspace partition journal and draft keys. Borrowed cloud data is restored to its original local source on disconnect/revocation/startup recovery; reopening cloud content after restart requires sign-in. Web Locks are acquired before any store index/lease recovery/write. Because all workspaces share an index, one origin-wide writer owns local storage. A second tab blocks safely; unsupported Web Locks fail closed. Closing the first tab permits takeover. This is single-writer support, not simultaneous same-origin independent editors. Separate authorized devices/accounts continue to use cloud revisions.

Retained journals/drafts contain private plaintext user intent. Scoped keys prevent accidental account mixing; they do not encrypt device storage or defend against another person with developer/storage access. Do not enable persistent Auth or silently expose borrowed data to solve restart usability. Production policy should combine explicit sign-in, device encryption/lock, owner-visible recovery export and deliberate cache deletion only after unsent work is recovered. Device-bound encryption/key recovery and shared-device acceptance remain production gates. No automatic journal purge or LRU discards pending work.

v1 local workspace/JSON/niyav and cloud backup v1/v2 readers are preserved. Large staged recovery and hidden-until-finalized imports remain. Journal storage reads legacy raw/v1 generations and migrates on a successful write to v2 content-addressed chunks. Current and previous complete generations remain; failed publication cannot replace the prior valid pointer. Drafts use separate scoped v1 keys. Journal v2 is not readable by the old v0.8.4 implementation: recover/acknowledge/export pending work using the new reader before reverting. Do not clear AsyncStorage, reset the tree or uninstall.
